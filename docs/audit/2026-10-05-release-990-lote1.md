## Rollback

| Situação | Ação | ETA |
|---|---|---|
| Problema só na jornada nova | Remover `CAMPAIGN_JOURNEY_ENABLED` do SSM (restaurar a versão anterior do parâmetro) e rodar o deploy no mesmo SHA → telas antigas de volta | ~15 min |
| Problema geral após o deploy | Workflow de deploy de cada stack com `action=rollback`, `confirm_production=true` (volta ao target group anterior) | ~5 min |
| Problema de dados | Restaurar o snapshot `chatwoot-autonomia-prod-pre-990-lote1-*` (último recurso; migrations são aditivas, então o código anterior roda sobre o schema novo) | ~30–60 min |

Abortar e executar o rollback pré-aprovado se: healthz falhar, contagem de chaves do SSM cair, ou erro 5xx novo nas telas existentes.
