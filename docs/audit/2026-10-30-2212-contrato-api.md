# #2212 — contrato da API do cuidado (A2, B1, B2), 30/10/2026

Decisões já tomadas (Rodrigo, via Meta aprovar, 29 e 30/10):
- (a) o dono escreve a mensagem do privado e, com as palavras dele, para quem ela vai. A IA decide comentário a
  comentário se é o caso; o que não é fica com o dono. Sem palavra-gatilho;
- a tela de configurar é a CuidarDono do protótipo, aprovada; só "Pausar", sem "desligar de vez";
- os comentários que chegaram antes de ligar ficam com o dono, que decide no "Ler e mandar";
- o resumo "O que tem nos comentários" fica (A2), com eval pago dentro do teto de US$ 5;
- um privado por pessoa em cada post;
- tudo atrás da flag `meta_ads_comentarios_ia`, piloto nas contas 1, 16 e 18;
- Facebook: o privado pelo Messenger depende da `pages_messaging` (F4). Até lá, no Facebook a IA só responde em
  público e esconde, e a tela mostra o privado "em breve".

A mesma tela (CuidarDono e CuidarLigado) serve o post de Seus posts (B1) e o anúncio (B2). Muda só o alvo:
`target_kind` post ou ad.

## Endpoints

Seus posts (B1), com as mesmas guardas do `SeusPostsComentariosController`:
- flags `seus_posts`, `seus_posts_comentarios` e `meta_ads_comentarios_ia`; sem elas, 404;
- `?perfil=`;
- quem vê a caixa;
- ver: `posts_view`; mudar: `posts_manage`.

```
GET    seus_posts/posts/:post_id/cuidado            → Painel
PUT    seus_posts/posts/:post_id/cuidado            { message, para_quem, phrases[], status } → Painel
POST   seus_posts/posts/:post_id/cuidado/previa     { para_quem } → Previa
POST   seus_posts/posts/:post_id/cuidado/ler_antigos → { queued }
GET    seus_posts/posts/:post_id/resumo             → Resumo   (A2)
GET    seus_posts/cuidados                          → { cuidados: [{ post_id, care, network, results: { sent, replied } }] }
PUT    seus_posts/cuidados                          { status } → a mesma lista ("Pausar todos" / "Voltar a cuidar de todos")
```

O "Ler e mandar" marca `read_old` numa trava atômica (a segunda chamada recebe `already_read`). Se a Meta não
responde ao job (até 3 tentativas) ou recusa a leitura, a marca volta para `false` e o dono pode tentar de novo.

A lista e o "Pausar todos" valem só para o perfil aberto (`?perfil=`): o cuidado do post guarda a caixa do perfil
(`inbox_id`). Servem o selo "Cuidando" de cada cartão e a faixa do topo de Seus posts.

Anúncio (B2), com as guardas da aba de comentários do anúncio:
- flags `meta_ads_gestao`, a dos comentários da rede e `meta_ads_comentarios_ia`;
- ver: `meta_ads_view`; mudar: `meta_ads_manage`.

```
GET    crm/meta_ads/ads/:ad_id/cuidado              → Painel
PUT    crm/meta_ads/ads/:ad_id/cuidado              (mesmo corpo)
POST   crm/meta_ads/ads/:ad_id/cuidado/previa
POST   crm/meta_ads/ads/:ad_id/cuidado/ler_antigos
GET    crm/meta_ads/ads/:ad_id/resumo               (A2)
```

## Painel

```json
{
  "network": "instagram | facebook | both",
  "private_available": true,
  "care": "off | on | paused",
  "message": "texto do dono (≤ 1000 bytes UTF-8)",
  "para_quem": "palavras do dono (≤ 500)",
  "phrases": ["frase pública", "…"],
  "read_old": false,
  "results": { "sent": 0, "replied": 0, "skipped": 0 },
  "unanswered": 0,
  "older": 0,
  "to_see": [{ "id": "c-1", "network": "instagram", "author": "carla", "text": "…", "kind": "complaint | failed | unsure | unread | older | waiting | skipped", "conversation_path": "/app/…" }],
  "hidden": [{ "id": "c-2", "network": "instagram", "author": "x", "text": "…" }]
}
```

Campos do Painel:
- **`private_available`:** false no Facebook enquanto não houver a `pages_messaging`.
- **`results.sent`:** as conversas que nasceram do privado da IA com este cuidado (`meta_ads_comment.care_id`,
  `private_reply`).
- **`results.replied`:** dessas, as conversas em que a pessoa respondeu.
- **`results.skipped`:** os comentários que o "Ler e mandar" leu e que não eram o caso.
- **`unanswered`:** os comentários sem resposta, com até 7 dias e que chegaram antes de ligar (`started_at` do
  cuidado; sem cuidado, todos), que o "Ler e mandar" pode cuidar.
- **`older`:** os que passaram de 7 dias.
- **`to_see`:** o que ficou com o dono. `kind`: `complaint` (reclamação), `failed` (privado recusado), `unsure` (a
  Meta não respondeu ao privado: pode ter saído), `unread` (a IA não cuidou: Meta ou Jev fora do ar, teto do dia, sem
  certeza), `older` (mais de 7 dias), `skipped` (a IA leu e não era o caso) ou `waiting` (chegou antes de ligar). O
  que chegou depois de ligar e a IA ainda não leu está na fila dela e não entra.
- **`hidden`:** o que a IA escondeu.

O texto e o autor vêm da leitura ao vivo dos comentários (dado de terceiro, nunca gravado).

## Previa (CuidarDono, passo 3)

```json
{ "recebe": { "author": "…", "text": "…", "network": "instagram" } , "nao": { "author": "…", "text": "…" } }
```

Sem comentário que receberia: `"recebe": { "sample": true }`. Sem exemplo de "não se aplica": `"nao": null`.

Falha (a tela mostra "não deu para ler"): `422 { "error": "ai_unavailable" }` com o Jev fora do ar, `422 { "error":
"<status da leitura>" }` quando a Meta não leu, e `422 { "error": "invalid_para_quem" }` com o "para quem" vazio ou
acima de 500 letras.

A Previa classifica até 10 comentários recentes do post com o `para_quem` (Classificador). Custa cerca de
US$ 0,00024 por chamada.

## Resumo (A2, bloco "O que tem nos comentários")

```json
{ "status": "reading | ready | needs_permission | meta_unavailable", "questions": 0, "questions_old": 0, "complaints": 0, "read": 0, "more": false }
```

- **`reading`:** a primeira leitura roda num job (ResumoJob, sem nova tentativa); a tela pergunta de novo até vir
  `ready`.
- **Jev fora do ar:** a conta para, nada vai para o cache e a próxima pergunta recebe `422 { "error": "ai_unavailable" }`
  uma vez; a seguinte conta de novo.
- **O que entra:** até 30 comentários sem resposta, classificados com um critério fixo.
- **`questions`:** os pedidos de informação com até 7 dias (privado ou preço).
- **`questions_old`:** os mesmos pedidos, com mais de 7 dias.
- **`complaints`:** os de "para você".
- **Cache:** 1 hora por post, invalidado quando a lista de "esperando você" muda.
