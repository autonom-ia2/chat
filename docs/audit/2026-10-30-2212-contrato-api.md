# #2212 — contrato da API do cuidado (A2, B1, B2), 30/10/2026

Decisões já tomadas (Rodrigo, via Meta aprovar, 29 e 30/10):
- (a) o dono escreve a mensagem do privado e, com as palavras dele, para quem ela vai. A IA decide comentário a
  comentário se é o caso; o que não é fica com o dono. Sem palavra-gatilho;
- a tela de configurar é a CuidarDono do protótipo, aprovada; só "Pausar", sem "desligar de vez";
- os comentários que chegaram antes de ligar ficam com o dono, que decide no "Ler e mandar";
- o resumo "O que tem nos comentários" fica (A2), com eval pago dentro do teto de US$ 5;
- um privado por pessoa em cada post;
- tudo atrás da flag `meta_ads_comentarios_ia`, piloto nas contas 1, 16 e 18;
- Facebook: o privado pelo Messenger depende da `pages_messaging` (F4). Até lá, no Facebook a IA esconde propaganda e
  passa reclamação; a pergunta fica com o dono (`no_private`), sem resposta pública (a frase só acompanha o privado),
  e a tela mostra o privado "em breve".

A mesma tela (CuidarDono e CuidarLigado) serve o post de Seus posts (B1) e o anúncio (B2). Muda só o alvo:
`target_kind` post ou ad.

## Endpoints

Seus posts (B1), com as mesmas guardas do `SeusPostsComentariosController`:
- flags `seus_posts`, `seus_posts_comentarios` e `meta_ads_comentarios_ia`; sem elas, 404;
- `?perfil=`;
- quem vê a caixa;
- ver: `posts_view`; mudar: `posts_manage`.

```
GET    seus_posts/posts/:post_id/cuidado            → Painel
PUT    seus_posts/posts/:post_id/cuidado            { message, para_quem, phrases[], status } → Painel
POST   seus_posts/posts/:post_id/cuidado/previa     { para_quem } → Previa
POST   seus_posts/posts/:post_id/cuidado/rascunho   → { status: ready, message } | { status: no_offer } | { status: no_caption } | { status: no_credential }
                                                      | 422 ai_unavailable   (Rascunho, uma vez por legenda; só mudar)
POST   seus_posts/posts/:post_id/cuidado/ler_antigos → { queued }
GET    seus_posts/posts/:post_id/resumo             → Resumo   (A2)
GET    seus_posts/cuidados                          → { cuidados: [{ post_id, care, network, results: { sent, replied } }] }
PUT    seus_posts/cuidados                          { status } → a mesma lista ("Pausar todos" / "Voltar a cuidar de todos")
```

O começo da mensagem do passo 1 (`rascunho`, 30/10) sai da legenda lida na Meta, nunca do que a tela manda. Fica em
`crm_meta_ads_comment_drafts` com o digest da legenda: abrir de novo com a mesma legenda não chama a IA. O anúncio não
tem rascunho: o passo 1 abre vazio. O privado é só a mensagem do dono, sem aviso automático no fim (`automatic_note`
saiu do Painel).

O "Ler e mandar" marca `read_old` numa trava atômica (a segunda chamada recebe `already_read`). Se a Meta não
responde ao job (até 3 tentativas) ou recusa a leitura, a marca volta para `false` e o dono pode tentar de novo.

A lista e o "Pausar todos" valem só para o perfil aberto (`?perfil=`): o cuidado do post guarda a caixa do perfil
(`inbox_id`). Servem o selo "Cuidando" de cada cartão e a faixa do topo de Seus posts.

Anúncio (B2), com as guardas das abas de comentários do anúncio (`Crm::MetaAdsCuidadoController`), no mesmo escopo
`crm/meta_ads_connection` delas (corrigido em 30/10: o rascunho dizia `crm/meta_ads/ads`):
- flags `meta_ads_gestao`, `meta_ads_comentarios_ia` e a dos comentários de ao menos uma rede
  (`meta_ads_comentarios_instagram`, `meta_ads_comentarios_facebook`); sem elas, 404;
- conexão ativa com conta de anúncios e anúncio dessa conta; senão, 404 (`not_connected`, `ad_not_found`);
- as redes do cuidado vêm do criativo (`Crm::MetaAds::ComentariosIa::Anuncio`): só as com post, flag e caixa na conta.
  Sem nenhuma, 422 `no_post` ou `no_inbox`;
- ver a caixa de **todas** as redes do anúncio (InboxPolicy#show?), não só de uma; senão, 403 `not_inbox_member`
  (decisão de 30/10, mais segura: o Painel junta as redes e o "Ler e mandar" age nas duas). A checagem vem depois de
  ler o criativo (é ele que diz as caixas) e antes de ler os comentários. O criativo é lido uma vez só por chamada: a
  leitura dos comentários reusa a mesma `AdManagement`;
- a Meta fora do ar ao ler o anúncio: 422 `meta_unavailable`;
- ver: `meta_ads_view`; mudar: `meta_ads_manage`.

No painel, a entrada do anúncio e a rota da tela (`campaigns_meta_ads_cuidar`) pedem as mesmas flags, inclusive a de
ao menos uma rede.

```
GET    crm/meta_ads_connection/cuidados                    → { cuidados: [{ ad_id, care }] }   (selo, só banco)
GET    crm/meta_ads_connection/ads/:ad_id/cuidado          → Painel + inbox_id
PUT    crm/meta_ads_connection/ads/:ad_id/cuidado          (mesmo corpo) → Painel + inbox_id
POST   crm/meta_ads_connection/ads/:ad_id/cuidado/previa
POST   crm/meta_ads_connection/ads/:ad_id/cuidado/ler_antigos
GET    crm/meta_ads_connection/ads/:ad_id/resumo           (A2)
```

No anúncio, o Painel vem com `inbox_id`: a caixa do "Ver na caixa" (a do Instagram, por onde sai o privado, quando o
anúncio roda nele), lida na hora do criativo. A coluna `inbox_id` do cuidado fica nil no anúncio (só o post a usa). O alvo guardado é `{ kind: 'ad', ad_id, networks, post_ids }`; `post_ids` são os posts do criativo
(`effective_instagram_media_id`, `effective_object_story_id`), por onde o motor acha o cuidado do comentário que chega
sem o id do anúncio. Se o criativo troca de post (ou de redes), o Painel atualiza `post_ids` e `network` do cuidado
quando é lido. Vários cuidados de anúncio com o mesmo post: vale o mais antigo (menor id); o do anúncio sempre vence o
do post.

## Painel

```json
{
  "network": "instagram | facebook | both",
  "private_available": true,
  "care": "off | on | paused",
  "message": "texto do dono (≤ 1000 bytes UTF-8)",
  "para_quem": "palavras do dono (≤ 500)",
  "phrases": ["frase pública", "…"],
  "read_old": false,
  "results": { "sent": 0, "replied": 0, "skipped": 0 },
  "unanswered": 0,
  "older": 0,
  "to_see": [{ "id": "c-1", "network": "instagram", "author": "carla", "text": "…", "kind": "complaint | failed | unsure | unread | already_sent | no_private | older | waiting | paused | skipped", "conversation_path": "/app/…" }],
  "hidden": [{ "id": "c-2", "network": "instagram", "author": "x", "text": "…" }]
}
```

Campos do Painel:
- **`private_available`:** false no Facebook enquanto não houver a `pages_messaging`.
- **`results.sent`:** as conversas que nasceram do privado da IA com este cuidado (`meta_ads_comment.care_id`,
  `private_reply`), só as que quem abre a tela vê.
- **`results.replied`:** dessas, as conversas em que a pessoa respondeu.
- **`results.skipped`:** os comentários que o "Ler e mandar" leu e que não eram o caso.
- **`unanswered`:** os comentários sem resposta, com até 7 dias e que chegaram antes de ligar (`started_at` do
  cuidado; sem cuidado, todos), que o "Ler e mandar" pode cuidar. Voltar a cuidar (de pausado para ligado) recomeça
  `started_at` e libera o "Ler e mandar" de novo: o que chegou com o cuidado pausado passa a ser "antes de ligar".
  Com a flag `meta_ads_comentarios_ia` (#2454, o fio conta), entram também as respostas de cliente dentro
  dos comentários (à mostra, sem privado e sem a conta responder no fio depois delas), e o "Ler e mandar" as põe na
  fila do motor com o id do de cima. As respostas da própria conta não contam. `to_see` continua só com os de
  primeiro nível.
- **`older`:** os que passaram de 7 dias (com a flag, também as respostas).
- **`to_see`:** o que ficou com o dono. `kind`: `complaint` (reclamação), `failed` (privado recusado), `unsure` (a
  Meta não respondeu ao privado: pode ter saído), `unread` (a IA não cuidou: Meta ou Jev fora do ar, sem
  certeza, ou a Meta não escondeu), `already_sent` (era o caso do privado, mas a pessoa já tem um deste post),
  `no_private` (era o caso do privado, mas ele não sai ali: Facebook até a F4, ou cuidado sem oferta nem "para
  quem"; ação `kept_for_owner`), `older` (mais de 7 dias), `skipped` (a IA leu e não era o caso), `waiting` (chegou
  antes de ligar) ou `paused` (chegou com o cuidado pausado). O que chegou depois de ligar, com o cuidado ligado, e a
  IA ainda não leu está na fila dela e não entra.
- **`hidden`:** o que a IA escondeu.
- **`status`:** `ready`, ou o motivo de não ter lido os comentários (`needs_login`, `needs_permission`,
  `meta_unavailable`, `no_post`, `ad_not_found`…), com 200: o cuidado vem, sem a lista. A tela mostra o motivo, com
  "Tentar de novo" só em `meta_unavailable`.
- **`network_status`** (#2522): o status da leitura de cada rede, `{ "instagram": "ready", "facebook": "needs_login" }`.
  No anúncio nas duas redes, a falha numa não esconde a outra: `status` fica `ready`, a lista é a da rede que leu, e a
  tela avisa qual rede faltou e por quê. Só quando nenhuma rede leu, `status` é o motivo.

Erros da leitura do Painel (422 `no_post`, `no_inbox`, `meta_unavailable`, `needs_login`; 404 `not_connected`,
`ad_not_found`) têm texto próprio na tela; "Tentar de novo" só no que passa sozinho (`meta_unavailable`, rede).

O texto e o autor vêm da leitura ao vivo dos comentários (dado de terceiro, nunca gravado).

## Previa (CuidarDono, passo 3)

```json
{ "recebe": { "author": "…", "text": "…", "network": "instagram" } , "nao": { "author": "…", "text": "…" } }
```

Sem comentário que receberia: `"recebe": { "sample": true }`. Sem exemplo de "não se aplica": `"nao": null`.

Falha (a tela mostra "não deu para ler"): `422 { "error": "ai_unavailable" }` com o Jev fora do ar, `422 { "error":
"<status da leitura>" }` quando a Meta não leu, e `422 { "error": "invalid_para_quem" }` com o "para quem" vazio ou
acima de 500 letras.

A Previa classifica até 10 comentários recentes do post com o `para_quem` (Classificador). Custa cerca de
US$ 0,00024 por chamada.

Com a flag `meta_ads_comentarios_ia` (#2454), vem também `resposta`: a primeira resposta de outra pessoa
dentro de um dos comentários lidos, decidida com o de cima (uma chamada a mais). `null` sem resposta ou sem decisão
que caiba em "recebe" ou "não se aplica". Sem a flag, a chave não vem.

```json
{ "recebe": { "id": "…", "author": "…", "text": "…", "network": "instagram" },
  "nao": { "id": "…", "author": "…", "text": "…", "network": "instagram" },
  "resposta": { "author": "…", "text": "…", "network": "instagram", "kind": "recebe | nao",
                "parent": { "id": "…", "author": "…", "text": "…", "network": "instagram" } } }
```

Com a flag, cada exemplo leva o `id` do comentário. A tela mostra a resposta dentro do cartão do comentário de cima,
logo abaixo dele, quando ele é o `recebe` ou o `nao` (o de cima aparece uma vez só); quando não é, mostra o de cima
como contexto, sem selo, e a resposta abaixo. Com `kind: "recebe"`, o texto é "Tento mandar no privado; se a
rede não deixar, respondo só aqui": a Meta decide se aceita o privado em resposta.

## Respostas dentro de um comentário (motor, #2454)

Com a flag `meta_ads_comentarios_ia`:

- **Quem entra:** a resposta de cliente, decidida como um comentário próprio. O comentário de cima é lido na Meta pelo
  id (o evento só leva ids) e vai ao Classificador no campo `parent_comment`, nunca nas instruções.
- **Quem não entra:** a resposta da própria conta (perfil ou Página, inclusive a frase pública da IA).
- **Privado em resposta:** vai à Meta, sem recusa antes. O teste real é do próprio produto, na conta piloto, depois do
  deploy. Recusa 4xx com código é final: a pessoa recebe só a frase pública que não promete o privado (o preço, se o
  dono ligou essa chave); sem ela, o comentário fica com o dono (`kept_for_owner`). Falha passageira segue a regra de
  sempre (sem confirmação e travada). Limite de chamadas da Meta (códigos 4, 17, 32, 613, 80001, 80002, 80006 ou HTTP
  429, pela página "Rate Limiting" da Graph API) não é recusa: o job tenta de novo, com a pessoa ainda reservada para
  aquele comentário. Um privado por pessoa em cada post continua valendo.
- **Resultado consultável** (`crm_meta_ads_comment_actions`, sem texto de terceiro): aceito, a linha `private_reply`
  tem `meta_message_id`; recusado, a linha `private_reply_failed` tem `meta_error_code` e `meta_error_subcode`.

```sql
SELECT action, actor, comment_id, meta_message_id, meta_error_code, meta_error_subcode, at
FROM crm_meta_ads_comment_actions
WHERE account_id = <conta> AND (meta_message_id IS NOT NULL OR meta_error_code IS NOT NULL)
ORDER BY at DESC;
```

Sem a flag, tudo como antes: a resposta fica fora do motor e o InstagramPrivateReply recusa com
`private_reply_top_only`.

## Foto ("O que eu vi na foto", passo 1, #2454)

`POST .../cuidado/foto` (ler) e `PUT .../cuidado/foto` com `correction` (corrigir), no post do Seus posts e no anúncio.
Só com a flag `meta_ads_comentarios_ia` (sem ela, 404) e com a chave de mudar o cuidado (`posts_manage` ou
`meta_ads_manage`). Sempre 200:

```json
{ "status": "ready | no_image | no_credential | unavailable", "text": "…", "corrected": false }
```

- **Quando:** só o passo 1 pede, depois do clique. O resumo de antes do clique nunca lê a foto.
- **Uma vez por post:** a leitura fica em `crm_meta_ads_post_readings`; abrir de novo lê do banco.
- **`text`:** a correção do dono, quando existe; senão, o que a IA viu. É o que o Classificador recebe no campo `photo`.
- **Anúncio nas duas redes:** a tela lê e mostra a foto do primeiro post. Na prévia e no motor, cada comentário decide
  com a leitura do post da própria rede; a rede sem leitura decide sem foto.
- **`no_credential`:** a conta sem a chave dela (hook crm_kanban_ai); a da instalação nunca serve. Nada é gravado.
- **`unavailable`:** IA ou Meta fora do ar. Nada é gravado.
- **`no_image`:** o post não tem imagem; a tela não mostra o bloco.
- **Corrigir:** até 1000 letras (`422 invalid_correction` acima disso ou fora do formato); `correction: ""` volta para a
  leitura da IA. Sem a chave `correction`, `422 missing_correction`, e nada muda.

## Resumo (A2, bloco "O que tem nos comentários")

Desde o #2454, antes do clique do dono em "Cuidar dos comentários" não há chamada de IA: o Resumo só conta, na mesma
leitura da Fonte, e responde na hora (sem job, sem cache, sem `reading` e sem `ai_unavailable`).

```json
{ "status": "ready | needs_permission | meta_unavailable", "waiting": 0, "private_window": 0 }
```

- **`waiting`:** os comentários que esperam o dono (de outra pessoa, não escondidos, sem resposta da conta e sem
  privado). Com a flag `meta_ads_comentarios_ia`, também as respostas de cliente dentro deles (o fio conta,
  #2454): com todos esperando, o número bate com o de comentários que a Meta mostra.
- **`private_window`:** desses, os que ainda cabem no privado (até 7 dias). Sem a data do comentário, não cabe.
- **`status`:** `ready`, ou o motivo de não ter lido os comentários, com 200 e sem os números.
