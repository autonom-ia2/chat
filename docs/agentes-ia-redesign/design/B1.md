## 1. Resultado que o B1 precisa entregar

O B1 fecha as duas exposições de dados e configuração que já existem, cria o caminho controlado para
alterações operacionais feitas por SuperAdmin e torna observáveis as recusas e limites. O comportamento
esperado é:

1. `config` aceito pelo create e pelo PATCH público é uma lista fechada. Uma chave fora dela falha com
   `422`, código estável `config_key_not_allowed` e o nome da chave; o blob salvo permanece igual.
2. O drilldown de conversas do Analytics usa a mesma filtragem de permissão do produto. FAQ exige
   `autonomia_manage` para entrar na lista; aprovar e ignorar já são escritas de `autonomia_manage`.
3. As chaves operacionais que o BE-19 fecha só podem ser alteradas pelo caminho de SuperAdmin, por
   agente, com uma linha de `AuditLog` sanitizada e transação atômica.
4. Recusas do conjunto do B1 respondem `{ error, code }` estável em inglês e pt-BR, sem quebrar o
   texto legado que consumidores existentes leem.
5. `GET build_threads/:id` exige `autonomia_manage`, tal como as ações que já criam ou alteram a
   thread.
6. A janela de geração presa vem do tempo real das tentativas do cliente de IA: `180 * (2 + 1) +
   60 = 600` segundos (10 minutos), e o `409 build_in_progress` continua valendo dentro dela.
7. O Rack::Attack limita as portas de IA por conta e hash do token, sem mudar o responder global de
   `429`; os limites são configuráveis por ENV e comportam o tester e o Guia antes de qualquer leitura
   ao vivo.
8. O reaper protege rascunho que tenha qualquer resposta do usuário em uma thread do Construtor, além
   das proteções já existentes para instrução e material. Nenhum dado é destruído.

Não há migration neste desenho: `autonomia_agents.config` e `autonomia_agent_build_threads.state` já
são `jsonb`, e `audits` já existe no schema. A conclusão “zero migration” só vale se o PR mantiver as
mudanças aditivas nesses campos e no código; o CI deverá confirmar que nenhuma migration foi adicionada.

## 3. Desenho por mecanismo

### 3.1 Contrato de erro comum — BE-10

Ampliar o helper privado de `BaseController` para aceitar um `code` obrigatório nas recusas que o B1
padroniza e um pequeno conjunto explícito de metadados seguros. O envelope mínimo continua compatível:

```json
{ "error": "Chave de configuração não permitida.", "code": "config_key_not_allowed", "key": "native_tool_slugs" }
```

Regras:

- `error` é a mensagem localizada; `code` é máquina, estável e igual em `en` e `pt_BR`.
- `key` só aparece em `config_key_not_allowed` e contém apenas o nome da chave recusada. Nunca incluir
  valor de `config`, instrução, scaffold, token ou telefone.
- A ausência de `code` em uma chamada existente deve virar um caso de spec, não um fallback silencioso.
- O responder global de Rack::Attack não será alterado no B1: `429` continua com o envelope atual
  `{ error: { code: "rate_limited", message: ... } }` e `Retry-After`. O front lê `error.code` para
  a frase pt-BR prevista no PRD.
- As mensagens novas entram nos catálogos inglês e pt-BR. Os códigos cobertos pelo B1 são
  `config_key_not_allowed`, `instrucao_mantida`, `missing_instruction`, `missing_test`,
  `internal_with_channels`, `agent_internal_not_connectable`, `agent_not_active`,
  `inbox_has_webhook_bot`, `inbox_already_connected`, `not_connected`, `copilot_unavailable`,
  `no_guided_version`, `publish_field_not_allowed`, `invalid_phone`, `integration_not_configured`,
  `remote_setup_failed` e `account_token_missing`, conforme cada porta existente.

### 3.2 Fechamento da escrita de `config` — BE-19

Usar um único guard de escrita, chamado antes de qualquer `assign_attributes` ou `merge`, no caminho
comum de create/PATCH. O guard recebe a origem (`public_api` ou `super_admin_operation`) e a conta do
agente; ele não lê nem altera valores de chaves protegidas.

**Lista pública fechada, exatamente a do PRD:**


**Lista operacional do BE-31, proibida no PATCH público:**

```text

test_allowlist_phones

```

O guard deve:

1. normalizar somente os nomes das chaves permitidas pelo parser do Rails; não converter valores
   malformados em valores oficiais;
2. rejeitar a primeira chave fora da lista com `422 config_key_not_allowed` e `key`, antes de tocar o
   agente;
3. rejeitar também `system_key`, `hidden_from_hub`, qualquer `guide_*`, toda chave do BE-31 e todas
   as chaves hoje protegidas por `PROTECTED_CONFIG_KEYS` quando chegam pelo endpoint público;
4. mesclar apenas os campos públicos aceitos e preservar as chaves calculadas pelo Construtor/model;
5. manter a lista por conta via `agents_scope`, inclusive para cross-tenant, e manter a regra de
   agente de Cotação (`InstrucaoMantida`);
6. deixar escrita do model, Seed do Guia e `QuoteAgent::Builder` fora desse guard, como já exige o
   contrato do PRD, mas adicionar testes que garantam que esses escritores não sejam acidentalmente
   movidos para o endpoint público;
7. fazer o create usar o mesmo contrato: não basta corrigir `merge_config!`, porque hoje
   `agent_params` aceita `config: {}` também no nascimento.

O erro deve acontecer antes da alteração persistente. O spec deve reler `config` depois da resposta e
provar igualdade byte a byte/json sem a chave recusada ser descartada silenciosamente. A foto Q12b não
é produzida nem limpa pelo B1; a mudança do contrato só impede novas gravações.

### 3.4 Porta de operação do SuperAdmin — BE-31

Criar um serviço transacional por agente para alterar somente a lista do BE-31. A tela e a rota ficam
no namespace SuperAdmin, sob a conta escolhida, e nunca reutilizam o PATCH público de agentes. A rota
proposta, aninhada ao recurso `accounts` já existente, é:

```text
PATCH /super_admin/accounts/:id/agents/:agent_id/operation_config
body: { operation_config: { <chave BE-31>: <valor> } }
```

O controller será `SuperAdmin::AccountsController#update_agent_operation_config`, usando a conta

- só `current_super_admin` passa; usuário da conta e usuário com `autonomia_manage` recebem `401/403`
  conforme o padrão do controller;
- `Agent.find_by!(account_id: requested_account.id, id: params[:agent_id])` é a forma de resolver o
  agente; nunca aceitar id global fora da conta selecionada;
- agentes com `config['system_key']` ficam fora da lista e não podem ser alterados por este caminho;
- Lia (`insurance_quote`) não oferece `native_tool_slugs`; os demais campos da lista continuam sujeitos
  à decisão fechada do PRD;

- a auditoria é criada na mesma transação com `Audited.audit_class` (que resolve para
  `Enterprise::AuditLog` no ambiente Enterprise), `auditable` = agente, `associated` = conta,
  `user` = SuperAdmin, `action` = atualização operacional;
- `audited_changes` contém apenas o evento, ids, chaves alteradas e valores sanitizados. Se a chave
  for `test_allowlist_phones`, telefones são mascarados antes do registro; nunca entram
  `instruction`, `scaffold`, prompt ou conteúdo da base. Falha ao persistir a auditoria reverte a
  alteração, seguindo a garantia já usada em `SoftDelete` (`soft_delete.rb:17-22`);
- o registro aparece no fluxo de AuditLog já existente (`enterprise/app/models/enterprise/audit_log.rb:30-32`

  migration nova.

O teste de isolamento altera uma chave em um agente criado para o tester e confirma: o agente alvo
mudou, a linha de auditoria existe, o conteúdo não contém instrução/scaffold/telefone sem máscara e
nenhum outro agente da conta mudou.

### 3.6 Janela de geração presa — BE-15

Substituir o literal de `BuildThread` por uma constante derivada do cliente que realmente faz as
tentativas:

```ruby
STALE_PROCESSING_AFTER =
  Crm::Ai::ResponsesClient::REQUEST_TIMEOUT * (Crm::Ai::ResponsesClient::MAX_RETRIES + 1) + 1.minute
```

As constantes de origem estão em `app/services/crm/ai/responses_client.rb:9-10` (`180` e `2`), portanto

ou job duplicado; depois da janela → novo token, mensagem e job; o teste deve calcular o instante a
partir da constante, não repetir `5.minutes`.

### 3.7 Throttles por conta e token — BE-20

Adicionar regras ao `config/initializers/rack_attack.rb` para estas portas:

| Porta | Método e caminho normalizado |
|---|---|
| Construtor | `POST /api/v1/accounts/:account_id/autonomia/build_threads`, `/build_threads/:id/messages` e `/build_threads/:id/retry` |

- provar que tokens diferentes têm buckets diferentes na mesma conta, que a mesma credencial em contas

```sql
SET LOCAL lock_timeout = '1s';

WITH stale_links AS (
  SELECT a.account_id,
         a.id AS agent_id,
         ai.inbox_id,
         ai.agent_bot_id
    FROM autonomia_agents AS a
    JOIN autonomia_agent_inboxes AS ai
      ON ai.autonomia_agent_id = a.id
     AND ai.account_id = a.account_id
     AND ai.deleted_at IS NULL
    JOIN inboxes AS i
      ON i.id = ai.inbox_id
     AND i.account_id = ai.account_id
    JOIN agent_bot_inboxes AS abi
      ON abi.inbox_id = ai.inbox_id
     AND abi.agent_bot_id = ai.agent_bot_id
     AND abi.account_id = ai.account_id
     AND abi.status = 0             -- AgentBotInbox.active
    JOIN agent_bots AS ab
      ON ab.id = ai.agent_bot_id
     AND ab.account_id = ai.account_id
     AND ab.outgoing_url IS NULL    -- espelho nativo, não webhook
   WHERE a.deleted_at IS NOT NULL
      OR a.enabled IS NOT TRUE
      OR a.status <> 1              -- Agent.active
      OR a.actuation = 1            -- Agent.actuation_internal
      OR a.config->>'system_key' IS NOT NULL
), stuck AS (
  SELECT DISTINCT sl.account_id,
                  sl.agent_id,
                  sl.inbox_id,
                  sl.agent_bot_id,
                  c.id AS conversation_id
    FROM stale_links AS sl
    LEFT JOIN conversations AS c
      ON c.account_id = sl.account_id
     AND c.inbox_id = sl.inbox_id
     AND (
       c.status = 2                 -- pending
       OR (c.status = 0              -- open
           AND c.assignee_agent_bot_id = sl.agent_bot_id)
     )
)
SELECT account_id,
       agent_id,
       COUNT(DISTINCT inbox_id) AS links_with_active_mirror,
       COUNT(DISTINCT conversation_id) AS stuck_conversations
  FROM stuck
 GROUP BY account_id, agent_id
 ORDER BY account_id, agent_id;

ROLLBACK;
```

Saída vazia é o resultado esperado. Qualquer linha é apenas uma foto para decisão; nenhuma correção
(`sync_mirror!`, `release_bot_conversations!` ou UPDATE) está autorizada por este documento.
