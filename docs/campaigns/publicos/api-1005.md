# Públicos sem etiqueta — envio para a lista do público (#1005)

Refs #990. Itens do #993 que são do envio no WhatsApp Oficial: D2, D4, D5, D6. Aceites do PRD
cobertos: N1–N4, D2, D4, D5, D6, J4, J5/J6 (endpoint), A4 (API), B1b (no envio), F1, F2.

## 1. O que mudou no comportamento

| Antes | Agora |
|---|---|
| Salvar um público criava a etiqueta base escondida (`campanha_<slug>_<id>`) e marcava os contatos | Público (`flow: "audience"`) **não cria etiqueta nenhuma**: nem `Label`, nem `campaign_import_labels`, nem tagging (N1). `batch_count = 1` (D3). A importação antiga (Base Campanha) continua igual (N3). |
| Campanha de WhatsApp Oficial sempre ia para as etiquetas de `campaign.audience` | Campanha **ligada a um público** (`campaign_audience_links`) vai para os contatos do público (N2). Campanha sem vínculo continua pelas etiquetas (N3). |
| "Excluir público" só antes de salvar | Público pode ser excluído também depois de salvo: apaga **só a lista** (F2/N4). |

## 2. Dados

Tabela nova do fork `campaign_audience_links` (migration `20261005130000`), sem coluna nova em
tabela do Chatwoot:

| coluna | |
|---|---|
| `account_id` | FK `accounts`, `ON DELETE CASCADE` |
| `campaign_type`, `campaign_id` | campanha de qualquer motor (`Campaign` hoje; `EmailCampaign`/`WhatsappApiCampaign` no #999). Índice **único** em `(campaign_type, campaign_id)` |
| `campaign_import_id` | o público. FK `ON DELETE SET NULL`: excluir o público desliga o vínculo e a campanha fica |
| `variable_bindings` (jsonb) | variáveis da mensagem (item 4) |
| `variable_defaults` (jsonb) | texto padrão por variável |

As variáveis ficam no vínculo (e não numa tabela à parte) porque só existem para campanha que
envia para público e têm o mesmo ciclo de vida do vínculo.

Contatos do público = `campaign_import_rows.contact_id` das linhas `imported`
(`CampaignJourney::AudienceContacts.contacts_for(link, channel: :whatsapp)`), filtrados por:

- WhatsApp: contato com `phone_number`;
- recusa de mensagens (#737): contato com `opted_out_at` fica **fora do total** (não vira
  destinatário, PRD B8). Quem recusa **durante** o envio é pulado com `opted_out` (D5).

## 3. Envio (WhatsApp Oficial)

Módulos do fork prependados em `Whatsapp::OneoffCampaignService` por
`config/initializers/campaign_journey.rb` (o serviço e o overlay `enterprise/` não foram
editados):

- `CampaignJourney::AudienceContacts` — troca etiquetas pelos contatos do público quando há
  vínculo (`create_recipients` no caminho Enterprise, `process_audience` no OSS).
- `CampaignJourney::WhatsappOneoffRecipients` (só com Enterprise, onde existe
  `CampaignRecipient`):
  - **D2**: antes da primeira mensagem, um `campaign_recipient` `queued` para cada contato
    elegível (insert em lote, idempotente por campanha + contato); só os `queued` são
    processados (reprocessar a campanha não reenvia). Ao fim, nenhum destinatário fica sem
    situação: sobra `queued` vira `failed` "Recipient was not processed".
  - **D4**: erro do provedor → `failed` com o motivo da Meta (`error_user_msg`, ex.: "Número
    sem WhatsApp") — já era o comportamento do overlay; erro inesperado em um destinatário →
    `failed` "Unexpected error while sending (<Classe>)"; os demais seguem.
  - **B1b**: variáveis resolvidas por pessoa (item 4). Sem valor e sem texto padrão →
    `skipped` com `error_message = "falta {{2}}"` (várias: `"falta {{1}}, {{2}}"`).
  - `message_content` do destinatário guarda o texto com os valores daquela pessoa.
  - O tratamento de D2/D4 (rescue por destinatário e varredura dos `queued`) vale **também para
    campanhas antigas por etiqueta** (decisão do Rodrigo): o público delas não muda; só ninguém fica
    sem situação.

Os valores das variáveis entram **depois** do Liquid do modelo: texto da planilha nunca é
interpretado como Liquid.

**D6**: resposta de número sem o 9 cai no contato importado (e na conversa que ele já tem na
caixa) pela busca de candidatos do upstream (fix 9550de83e4). Spec de aceite com webhook Cloud
simulado: `spec/jobs/webhooks/whatsapp_events_job_ninth_digit_spec.rb`.

## 4. Criar campanha da jornada

`POST /api/v1/accounts/:account_id/campaign_journey/campaigns` (JSON)

```json
{
  "campaign_import_id": 42,
  "channel": "whatsapp_cloud",
  "campaign": {
    "title": "Renovação auto — outubro",
    "inbox_id": 7,
    "scheduled_at": "2026-10-06T12:00:00.000Z",
    "message": "opcional",
    "template_params": { "name": "renovacao_auto_v2", "namespace": "…", "category": "MARKETING", "language": "pt_BR",
                         "processed_params": { "body": { "1": "", "2": "", "3": "Equipe Hub2You" } } },
    "variable_bindings": {
      "1": { "source": "contact", "value": "first_name" },
      "2": { "source": "column",  "value": "Vencimento" },
      "3": { "source": "fixed",   "value": "Equipe Hub2You" }
    },
    "variable_defaults": { "2": "em breve" }
  }
}
```

- Cria a `Campaign` pelo model (validações normais; `one_off`; `audience: []`) e o vínculo na
  mesma transação — o agendador nunca vê a campanha sem público.
- `scheduled_at`: ISO 8601 ou `null` (= agora, regra do model).
- `template_params`: mesmo formato do `POST /campaigns` antigo.
- `message` (opcional, extensão do contrato): sem ele, o texto do corpo do modelo aprovado da
  caixa (com `{{N}}`); sem modelo achado, o nome do modelo.
- `variable_bindings` (chave = variável do corpo):
  - `contact` → `value` ∈ `name`, `first_name`, `company` (empresa ligada ao contato; sem
    Enterprise, `additional_attributes.company_name`);
  - `column` → `value` = cabeçalho exato de `extra_columns` do público (checado com
    `CampaignImports::VariableCoverage`, #992);
  - `fixed` → `value` = texto (até 1024).
  Até 20 variáveis; `variable_defaults` só para chaves que existem em `variable_bindings`.

Respostas:

- `200 { "id", "display_id", "title", "channel": "whatsapp_cloud", "scheduled_at", "recipients_count" }`
  — `recipients_count` = contatos elegíveis agora (com celular, sem recusa). Quem ficar sem
  variável no envio entra como `skipped`, então Enviadas + Falharam + Puladas = esse total (E1).
- `422 { "error": "<mensagem em inglês>", "code": "..." }`:

| `code` | quando |
|---|---|
| `whatsapp_cloud_required` | `channel` ≠ `whatsapp_cloud`, caixa inexistente, não-WhatsApp ou WhatsApp não-Cloud (D1) |
| `audience_not_ready` | público fora de `completed` / `completed_with_failures` |
| `channel_not_in_audience` | J4: público com `channels.whatsapp.enabled = false` ou `count = 0` (importação antiga: sem contatos importados) |
| `invalid_variable_bindings` | **(novo)** fonte/campo desconhecido, coluna fora de `extra_columns`, texto fixo vazio, padrão sem variável |
| `invalid_campaign` | **(novo)** validação do model `Campaign` (ex.: título vazio) |

- `404` público de outra conta ou inexistente (`campaign_import_id`).
- **Permissão (A4)**: `campaign_manage` (`CampaignPolicy#create?`). Só `campaign_view` → `401`
  (padrão do Chatwoot para Pundit).
- **Flag**: `CAMPAIGN_JOURNEY_ENABLED` (ENV, a mesma que o dashboard lê no #993) desligada →
  `404 { "error": "campaign_journey.disabled", "code": "campaign_journey_disabled" }`. Escolhi 404
  (e não 403) para seguir `CAMPAIGN_IMPORT_ENABLED`: o recurso "não existe" com a flag desligada.
  O endpoint não exige `CAMPAIGN_IMPORT_ENABLED`.

## 5. Ligar e desligar canal do público (J5/J6)

`PATCH /api/v1/accounts/:account_id/campaign_imports/:id/channels` (JSON, parcial)

```json
{ "email": false, "whatsapp": true }
```

- Atualiza `channels.<canal>.enabled`; `count` não muda.
- Ligar canal com `count = 0` → `422 { "error": "campaign_import.channel_without_data" }` (nada muda).
- Valor diferente de `true`/`false`, ou nenhum canal → `422 campaign_import.invalid_channels_choice`.
- Importação antiga → `422 campaign_import.not_an_audience`.
- Vale em qualquer status (desligar depois de salvo tira o público daquele canal).
- **Desligar** um canal enquanto uma campanha **não concluída** (agendada ou enviando) ligada ao
  público usa aquele canal (hoje: `Campaign` do WhatsApp Oficial → `whatsapp`) →
  `422 { "error": "campaign_import.audience_in_use", "code": "audience_in_use", "campaigns": [{ "title", "display_id" }] }`.
  Ligar continua livre (respeitando `channel_without_data`). O envio não relê o canal.
- `campaign_manage`; sem a permissão → `401`. Atrás de `CAMPAIGN_IMPORT_ENABLED` (404 desligado).
- `200` com o objeto `campaign_import` (mesmo do `show`).

> Decidido: a tela usa `PATCH .../channels` (este) e `PATCH .../companies` (#998). Não existe
> `audience_settings`.

## 6. Excluir público (F2/N4)

`DELETE /api/v1/accounts/:account_id/campaign_imports/:id` (endpoint existente)

- Público: permitido em qualquer status **exceto** `validating`, `confirmed`, `queued`,
  `importing`, `undoing_labels` (→ `422 campaign_import.delete_not_available`).
- Apaga só a lista (`CampaignImports::AudienceDeletion`): o `campaign_import`, suas linhas, seus
  registros de etiqueta e os arquivos. **Ficam**: contatos, empresas, ligações contato–empresa,
  conversas, campanhas e seus `campaign_recipients` (resultado). Os vínculos das campanhas ficam
  com `campaign_import_id = NULL`.
- **Bloqueado** quando alguma campanha ligada ao público ainda não concluiu (agendada ou enviando):
  `422 { "error": "campaign_import.audience_in_use", "code": "audience_in_use", "campaigns": [{ "title", "display_id" }] }`
  com só as campanhas não concluídas. Público usado apenas por campanhas concluídas é excluído
  normalmente.
- Se mesmo assim um vínculo ficar sem público (FK `SET NULL`), a campanha conclui sem destinatários.
- `can_delete` no objeto passa a refletir essa regra.
- Importação antiga: regra de antes (só antes de criar contatos).

## 7. Backfill das campanhas antigas (F1)

```sh
bundle exec rails campaign_journey:backfill_audience_links           # DRY-RUN: só conta
APPLY=1 bundle exec rails campaign_journey:backfill_audience_links   # grava
```

`CampaignJourney::AudienceLinkBackfill`: para cada `Campaign` `one_off` com etiquetas em
`audience`, procura a importação cuja **etiqueta base** (`campaign_import_labels.kind = base`,
`label_id`) está entre elas, na mesma conta. Contadores impressos:

| contador | |
|---|---|
| `campaigns_with_labels` | campanhas com etiquetas no público |
| `linked` | ligadas (no DRY-RUN: seriam ligadas) |
| `already_linked` | já tinham vínculo (idempotência) |
| `no_import` | nenhuma etiqueta é base de importação |
| `ambiguous` | etiquetas de mais de uma importação — não liga |
| `not_completed` | campanha ainda não concluída — **não liga**, porque o vínculo mudaria quem recebe (N3) |

Regras (confirmadas pelo Rodrigo):

- só campanhas **concluídas** são ligadas;
- só pela **etiqueta base** — etiqueta de lote não conta (uma campanha de um lote não é o público
  inteiro);
- campanhas **ambíguas** (etiquetas de mais de uma importação) ficam de fora;
- idempotente: quem já tem vínculo não é tocado.

Rodar em produção só com OK do Rodrigo, primeiro em DRY-RUN.
