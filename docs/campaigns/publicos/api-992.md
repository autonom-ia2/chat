# Públicos — contrato da API de colunas e variáveis (#992)

Refs #990. Backend do PR #992; as telas vêm no #993. Tudo atrás de `CAMPAIGN_IMPORT_ENABLED`
(desligado → `404 {"error":"campaign_import.disabled"}`). `index`/`show` pedem `campaign_view`;
criar, escolher colunas e os dois endpoints de variáveis pedem `campaign_manage` (sem a
permissão → `401`).

Base: `/api/v1/accounts/:account_id/campaign_imports`.

## 1. Criar um público

`POST /campaign_imports` (multipart)

| campo | obrigatório | |
|---|---|---|
| `name` | sim (é o que marca o fluxo Públicos) | nome do público |
| `import_file` | sim | `.csv` ou `.xlsx` |
| `create_companies` | não | `"false"` desliga "Criar e ligar" (#998); padrão ligado |

Sem `name`, o endpoint segue o fluxo antigo (Base Campanha: `campaign_name` + `batch_count`),
sem nenhuma mudança.

O público nasce com `flow: "audience"`, `batch_count: 1`, `mode: "single_label"` e a validação
roda em segundo plano (`CampaignImports::ValidateJob` → `AudienceValidator`). Resposta `201`
com o objeto do item 4. Acompanhe com `GET /campaign_imports/:id`.

## 2. Status

Os de sempre (`uploaded`, `validating`, `validation_failed`, `ready_to_confirm`, `queued`,
`importing`, `completed`, `completed_with_failures`, `failed`, …) mais um novo:

- **`needs_column_choice`** — as colunas não foram achadas com certeza (Jev desligado, fora do
  ar, com erro ou inseguro). Nenhuma linha foi gravada ainda. A tela mostra as colunas com as
  sugestões de `schema_resolution.targets` e pede a escolha (item 5). Pode ser excluído.

Depois da escolha: `validating` → `ready_to_confirm` (ou `validation_failed`). Salvar o público
continua sendo `POST /campaign_imports/:id/confirm` → `queued` → `importing` → `completed`.

## 3. Quem decide as colunas

Jev só é chamado com `CAMPAIGN_JOURNEY_JEV_ENABLED=true` (config de instalação, padrão `false`)
**e** chave TypeSafe configurada. `TYPESAFE_JEV_ENABLED` continua valendo só para a importação
de destinatários de e-mail.

| `schema_resolution.method` | quando | precisa escolher? |
|---|---|---|
| `jev` | Jev respondeu os 4 alvos com confiança ≥ 0,8, esquema ≥ 0,5, sem coluna repetida, e a coluna de celular/e-mail tem ao menos um valor válido | não |
| `deterministic` | qualquer outro caso; os aliases conhecidos só **pré-preenchem** a sugestão | sim (`needs_column_choice`) |
| `manual` | a pessoa escolheu pelo item 5 | não |

O pedido ao Jev leva só cabeçalhos, contagens (`non_blank_count`, `valid_phone_count`,
`valid_email_count`) e exemplos mascarados (`Aaa Aaaaa`, `(00) 00000-0000`, `[email address]`).
Nenhum nome, número ou e-mail da planilha sai do servidor (spec B4/Q1).

## 4. Objeto `campaign_import` (campos novos)

```json
{
  "id": 42,
  "status": "ready_to_confirm",
  "name": "Clientes renovação",
  "flow": "audience",
  "channels": {
    "email":    { "enabled": false, "count": 0 },
    "whatsapp": { "enabled": true,  "count": 2 }
  },
  "extra_columns": ["Vencimento"],
  "schema_resolution": { "...": "ver abaixo" },
  "total_rows": 2, "valid_rows": 2, "invalid_rows": 0,
  "validation_summary": { "errors": {}, "warnings": [], "companies": { "...": "ver item 9" } },
  "create_companies": true,
  "companies": { "created": 0, "reused": 0, "contacts_linked": 0, "kept": 0 }
}
```

- `flow`: `"audience"` (Públicos) ou `"campaign_base"` (importação antiga).
- `channels.*.count`: linhas válidas com e-mail válido / com celular brasileiro válido.
  `enabled` nasce `count > 0`. (Ligar/desligar: `PATCH .../channels`, ver `api-1005.md` §5.)
- `extra_columns`: cabeçalhos das colunas não ligadas a nome/celular/e-mail/empresa, como
  escritos na planilha; repetidos ganham ` (2)`, ` (3)`; coluna sem cabeçalho vira `column_N`.

### `schema_resolution`

```json
{
  "version": 1,
  "method": "deterministic",
  "needs_confirmation": true,
  "uncertain_targets": ["name", "phone", "email", "company"],
  "format": "csv", "delimiter": ";", "table_index": 0, "table_name": "CSV", "header_row": 1,
  "jev": { "status": "disabled" },
  "targets": {
    "name":    { "column": 0,    "header": "Segurado", "source": "alias", "confident": false, "confidence": null },
    "phone":   { "column": 1,    "header": "Fone 1",   "source": "jev",   "confident": false, "confidence": 0.62 },
    "email":   { "column": null, "header": null,       "source": null,    "confident": false, "confidence": null },
    "company": { "column": 2,    "header": "Corretora","source": "jev",   "confident": true,  "confidence": 0.97 }
  },
  "columns": [
    { "index": 0, "header": "Segurado",   "non_blank_count": 2, "valid_phone_count": 0, "valid_email_count": 0 },
    { "index": 1, "header": "Fone 1",     "non_blank_count": 2, "valid_phone_count": 2, "valid_email_count": 0 },
    { "index": 2, "header": "Corretora",  "non_blank_count": 2, "valid_phone_count": 0, "valid_email_count": 0 },
    { "index": 3, "header": "Vencimento", "non_blank_count": 1, "valid_phone_count": 0, "valid_email_count": 0 }
  ],
  "manual_mapping": { "name": 0, "phone": 1, "email": null, "company": 2 }
}
```

- `jev.status`: `answered` (com `model` e `schema_probability`), `disabled`, `failed` (com
  `error`, código sanitizado como `typesafe_unavailable`), `skipped` (escolha manual).
- `targets.*.source`: `jev`, `alias` (sugestão por cabeçalho conhecido), `manual` ou `null`.
  `confident: false` = a tela deve pedir confirmação desse alvo.
- `columns`: todas as colunas do cabeçalho achado, com contagens — base para o seletor manual.
  Sem valores de linha.
- `header_row`: linha (1-based) do cabeçalho; pode não ser 1 (B3).
- `manual_mapping`: só existe depois do item 5.

### Linhas (`campaign_import_rows`)

Campos novos: `email_masked` (`a**@alfa.com.br`), `normalized_email_hash` (SHA-256 do e-mail
normalizado), `company_name` (valor aparado, para o #998), `extra_values`
(`{"Vencimento": "10/2026"}`, só não vazios). Linha válida = celular válido **ou** e-mail
válido. Motivos novos em `error_messages`: `missing_contact`, `invalid_email`, `blank_email`,
`duplicate_email_in_file` (além de `duplicate_phone_in_file`, `invalid_brazilian_mobile_number`,
`formula_detected`). A primeira ocorrência de um celular ou e-mail vale; as repetidas ficam de fora.

Ao salvar, o contato é achado pelo celular (com ou sem o 9) e, se não houver, pelo e-mail sem
diferença de caixa; senão é criado com nome, celular e e-mail. Contato existente só ganha o que
lhe falta (e-mail já usado por outro contato não é copiado).

## 5. Escolher colunas

`PATCH /campaign_imports/:id/columns` (JSON)

```json
{ "name": 0, "phone": 1, "email": null, "company": 2 }
```

- Índices de `schema_resolution.columns`; `null` ou ausente = não há.
- Exige celular **ou** e-mail; índices distintos e existentes.
- Vale em `needs_column_choice`, `ready_to_confirm` ou `validation_failed` (trocar colunas).
- Resposta `200` com o objeto (status `validating`); a revalidação roda em segundo plano com
  as colunas escolhidas (`method: "manual"`), no mesmo cabeçalho achado antes.

Erros `422`: `campaign_import.invalid_column_choice`, `campaign_import.column_choice_not_available`
(status não permite), `campaign_import.not_an_audience` (importação antiga).

## 6. Sugestão de coluna para variável do modelo (B1)

`GET /campaign_imports/:id/variable_suggestions?variables[][key]=1&variables[][label]=nome&variables[][key]=2&variables[][label]=mês de vencimento`

- `label`: o rótulo da variável (ex.: o que ela representa). **Nunca** mandar valores de
  contato ou exemplos com dados de pessoas. Até 20 variáveis; rótulo cortado em 120 caracteres.
- Fontes possíveis: `name` e `company` ligados e todas as `extra_columns`.

```json
{ "payload": [
  { "key": "1", "source": { "source": "name" }, "confidence": 0.93 },
  { "key": "2", "source": { "source": "extra", "column": "Vencimento" }, "confidence": 0.91 }
] }
```

`source: null` = sem sugestão (Jev desligado, com erro ou com confiança < 0,8). O Jev recebe só
rótulos e cabeçalhos. A tela nunca menciona "Jev", "IA" ou modelo (B1a).

## 7. Linhas que ficam de fora por variável (B1b)

`POST /campaign_imports/:id/variable_coverage` (JSON)

```json
{
  "mapping":  { "1": { "source": "name" }, "2": { "source": "extra", "column": "Vencimento" } },
  "defaults": { "2": "em breve" }
}
```

`source`: `name`, `company` ou `extra` (com `column` de `extra_columns`). Considera linhas
`valid` e `imported`.

```json
{ "payload": {
  "included_count": 1,
  "excluded_count": 1,
  "excluded": [ { "row_number": 3, "missing": ["2"] } ],
  "missing_by_variable": { "2": 1 }
} }
```

`missing` lista as chaves sem valor e sem texto padrão — a tela mostra "falta {{2}}".
`excluded` vem limitado às 100 primeiras; os totais contam todas. Erro `422`
`campaign_import.invalid_variable_mapping` para fonte ou coluna desconhecida.

## 9. Empresas (#998)

Regras e dados em `companies-998.md`. Só Públicos; a importação antiga não mexe em empresas.

**Antes de salvar** (`ready_to_confirm`), `validation_summary.companies` traz o que salvar vai
fazer, sem gravar nada:

```json
{ "available": true, "rows_with_company": 10, "companies_created": 1,
  "companies_reused": 2, "contacts_linked": 9, "contacts_kept": 1 }
```

- `companies_created` = "novas"; `companies_reused` = "já existiam" (empresas distintas);
  `contacts_linked` = "contatos ligados" (inclui quem já tinha a mesma empresa);
  `contacts_kept` = "mantidas" (contato já tem outra empresa e continua com ela).
- `{ "available": false }` = conta sem a flag `companies`: a tela esconde a linha "Empresa" e o
  bloco Empresas (C6).
- Vale com o interruptor ligado ou desligado (não precisa revalidar ao trocar). Com
  `create_companies: false`, salvar não cria nem liga nada (C5) — a tela mostra o bloco desligado.

**Interruptor "Criar e ligar"**: `PATCH /campaign_imports/:id/companies` (JSON,
`campaign_manage`)

```json
{ "create_companies": false }
```

Vale em `uploaded`, `validating`, `needs_column_choice`, `ready_to_confirm` e
`validation_failed`. Resposta `200` com o objeto. Erros `422`:
`campaign_import.invalid_companies_choice` (valor diferente de `true`/`false`),
`campaign_import.companies_choice_not_available` (já salvo), `campaign_import.not_an_audience`.

**Depois de salvar**, `companies` traz os números finais, contados das linhas gravadas:
`created`, `reused`, `contacts_linked`, `kept` (mesmo significado da prévia; iguais a ela se
contatos e empresas não mudarem entre a validação e o salvar). Cada linha guarda
`company_id` e `company_result` (`created` | `reused` | `kept_other` | `none`).
